## Secrets Check
- `OGI_BOT_NSEC` is read from `process.env` in scripts/crawl/publish.ts, validated as a proper nsec (`nip19.decode`, type check), never logged, never written to disk. In crawl.yml it comes from `${{ secrets.OGI_BOT_NSEC }}` — correct.
- crawl.yml triggers are `schedule` + `workflow_dispatch` only — no `pull_request_target`, so fork PRs cannot exfiltrate the secret. Workflow permissions are scoped (`contents: write`); deploy.yml is minimal (`pages: write`, `id-token: write`, `contents: read`).
- Org-wide code search (`nsec1`, `"PRIVATE KEY"`, `password`, api-key patterns): no hits in this repo — no committed secrets.
- Reviewed: package.json, .mcp.json (two stdio MCP servers, no keys), .gitlab-ci.yml (legacy Pages config, no secrets), README.md — clean.
- run_secret_scanning unavailable (no GitHub Advanced Security); manual review + code search used instead.
