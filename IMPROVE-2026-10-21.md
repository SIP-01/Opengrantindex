# Improvement Deep-Dive — SIP-01/Opengrantindex — 2026-10-21

**ACTIVE repo** (github-actions[bot] commits a refreshed snapshot every ~6h; audit PR #1 merged 2026-10-21). This is a real improvement pass, not an archive review.

## Top recommendations (ranked, with effort S/M/L)

1. **SSRF guard for the CLI crawler — `scripts/crawl/net.ts` (S effort, high impact).** `fetchText()` does `fetch(url, { redirect: 'follow' })` with no destination validation. All seed URLs are hardcoded in `src/lib/ogi/seed/sources.ts` (good), but a compromised or domain-sniped source (26 sources, several small-community sites like aisafety.com, grantmakers.io) can 302 the crawler anywhere — including `169.254.169.254` (GitHub-hosted runners run on Azure; IMDS lives there) or internal runner network. Response bodies flow into `generated.json`, which is committed to the repo and deployed. Fix: port the battle-tested guard from `crawlstr/src/crawler/safety.ts` (handles odd IPv4 forms, IPv6 transition unfolding, CGNAT, metadata IPs), switch to `redirect: 'manual'`, and re-validate every `Location` target before following. That file is MIT and written as a superset union of two crawlers' guards — reuse it verbatim.
2. **Move `OGI_BOT_NSEC` out of workflow-level env (S, high impact).** In `.github/workflows/crawl.yml` the nsec is set in top-level `env:` — meaning **every step runs with the bot's signing key in its environment, including `npm ci`**, whose dependency postinstall scripts are arbitrary third-party code. Move it to the two crawl steps only (`env:` at step level). Same for `GITHUB_TOKEN` (only the crawl steps need it).
3. **Workflow hardening (S).** crawl.yml: no `timeout-minutes` (a hung crawl burns the 6h default); actions pinned by tag (`actions/checkout@v4` etc.) not by SHA — pin all actions to commit SHAs (both workflows); consider `persist-credentials: false` on checkout and an explicit `git push` remote config; `permissions: contents: write` is workflow-wide — scope to the job/step that commits.
4. **Add a CI gate that actually runs `npm test` (S/M).** No workflow runs the test script (`tsc + eslint + vitest + build`). The bot commits snapshot changes straight to `main` every 6h and `deploy.yml` deploys every push — a broken `generated.ts` codegen (e.g. from a parser change) ships to production untested. Minimum: run `npm test` inside crawl.yml before the commit step, and a PR-triggered ci.yml.
5. **Fix the stale live-demo link (S).** README advertises `https://ogi.shakespeare.wtf` — verified this session: HTTP 200 via nsite but `last-modified: 2026-07-25`, i.e. **a ~3-month-old bundle that embeds an equally old snapshot**. The fresh deployment is GitHub Pages (`https://sip-01.github.io/Opengrantindex/`, `last-modified` today, driven by deploy.yml on every bot commit). Repoint the README (and re-deploy or retire the nsite), or users land on stale data.
6. **Harden the RSS parser config (S).** `scripts/crawl/adapters/rss.ts` runs fast-xml-parser on untrusted feeds with `processEntities: true`. fast-xml-parser had a 2026 CVE chain (CVE-2026-25128 → 5.3.4; CVE-2026-25896 XSS → 5.3.5; CVE-2026-26278 entity-expansion DoS → 5.3.6; CVE-2026-27942 → 5.3.8; CVE-2026-33036 → 5.5.6; CVE-2026-41650 → 5.7.0; CVE-2026-73569 → 5.10.1 — verified via advisory search this session). `package.json` floors at `^5.11.1` (above all fixes — verify the lockfile pin matches), but the durable fix for untrusted RSS is parser options: `allowDoctypeDeclaration: false` (and `processEntities: false` if no feed legitimately needs entities).
7. **Prune or implement dead source adapters (M).** `runAdapter()` supports 5 adapters + RSS; most of the 26 declared sources use `html`/`sitemap`/`graphql`/`pdf`/`json-ld` endpoints and are `skipped` every run forever (`UNSUPPORTED_KINDS`). The `nostr-announcements` source even declares `schedule: '* * * * *'` with no adapter. Either implement the generic-html adapter or mark those sources `status: 'planned'` so `crawl-report.json` reflects reality (currently they pollute every report).

## Missing gates (CI/tests/protection)

- **No PR CI** (no workflow runs `npm test`) — the highest-value missing gate.
- **No branch protection on `main`** while a bot with `contents: write` pushes directly every 6h. At minimum protect against force-push/deletion; consider having the bot open auto-merge PRs so deploys get a checks pass.
- **No gitleaks** — the repo handles a long-lived nsec secret; a pre-commit/CI gitleaks job is cheap insurance against a future accidental commit of `OGI_BOT_NSEC`.
- crawl-report.json is committed but nothing alerts when a source stays in `error` for days — add a workflow step that fails (or opens an issue) when `errors > 0` persists. [S]

- Heartbeat source string inconsistency: `publish.ts` uses `INDEXER_SOURCE = 'OGI/1'` for the kind 16919 heartbeat `source` tag, but README documents `source: ogi-crawl/1`. Pick one (dashboards group on it). [S]
- `codegen()` embeds crawled JSON into `generated.ts` via `JSON.stringify` — safe as an expression, but add a size guard: the snapshot grows unboundedly (opportunities uncapped; awards capped at 1000). Cap opportunities too, or the Pages bundle inflates. [S]
- `sources.ts` `community` source homepage is `https://opengrantindex.org/submit` while the live site is on shakespeare.wtf/github.io — check the opengrantindex.org domain is actually owned/renewed before printing it in manifests. [S]
- `USER_AGENT` in net.ts still points to `github.com/NostrDanish/Opengrantindex` (old org). [S]
